# /defer-task — 세션 작업을 Notion으로 이월 (deferred task on a chosen date)

입력은 **이월할 날짜 하나**(`$ARGUMENTS`). **현재 이 대화 세션에서 한 작업**을 근거로,
**Work 페이지 캘린더(Work Tasks)** 와 **Daily 페이지 캘린더(Daily Tasks)** 두 곳 모두에
그 날짜로 뜨는 태스크를 만든다 (한 논리적 태스크 = 각 캘린더에 한 행씩, 본문 URL로 상호참조).
본문 3섹션: **(1) 이번 세션 하이레벨 요약 · (2) 남은 업데이트 · (3) action item 체크리스트.**
절대 없는 내용을 지어내지 않는다 — 근거(커밋/변경/테스트)에 기반하고, 불확실하면 "미확인"이라 적는다.
(/work-review는 지난 하루를 *평가*한다. /defer-task는 이번 세션을 *미래로 이월*한다 — 방향이 반대.)

> Notion MCP 도구가 deferred면 먼저 한 번에 로드:
> `ToolSearch("select:mcp__claude_ai_Notion__notion-search,mcp__claude_ai_Notion__notion-fetch,mcp__claude_ai_Notion__notion-create-pages,mcp__claude_ai_Notion__notion-update-page")`

## 고정 좌표 (Notion architecture — verified 2026-07-01)

- **Work Tasks** (Work 페이지의 📅 Work Calendar / 📥 Parking Lot) —
  `collection://d35b1602-d881-4925-8672-cd643bab375d`
  - props: `Name`(title), `Date`, `Due Date`, `Status`(Not Started/In Progress/Blocked/Done),
    `Impact`, `Priority`. **캘린더는 `Due Date` 기준.**
- **Daily Tasks** (🗓️ Daily 페이지의 캘린더) —
  `collection://08ef144c-aa66-4ebb-b213-b495e1621d9c`
  - props: `Name`(title), `Date`, `Status`(Not started/In progress/Done), `Impact`, `Priority`,
    `Tasks Table`(rel→GTD), `Projects`. **캘린더는 `Date` 기준.**
- **중요:** Work Tasks ↔ Daily Tasks 사이에는 **네이티브 관계 속성이 없다.** 그래서 "두 캘린더
  연결"은 관계가 아니라 **각 행 본문에 상대 행의 URL을 넣는 상호참조**로 한다.
- (별도 GTD **Tasks Table** `1f66048e…`는 이 명령과 무관 — 쓰지 않는다.)

## 1. 날짜 확정 (America/Toronto)

1. `$ARGUMENTS`가 비었으면 → **내일**. `tomorrow`/`today`/`+N`(N일 뒤)도 지원. 그 외엔 그 날짜.
2. Toronto 기준으로 확정: `TZ=America/Toronto date +%Y-%m-%d` (필요시 `-d "+1 day"`). → 대상일 `D`.
3. 날짜는 **날짜만**(시간 블록 아님): `is_datetime = 0`, 단일 `start = D`, `end` 비움.
   Work 행은 `Due Date = D`, Daily 행은 `Date = D`.

## 2. 이번 세션 내용 수집 → 3섹션 (근거 기반, 지어내지 않음)

이 대화 세션에서 실제로 한 일을 근거로 3섹션을 만든다. 근거: 이번 세션의 git 커밋
(`git log --oneline`으로 이번 세션 것만 골라냄 — 동시 세션 커밋은 제외), 수정 파일, 테스트 결과,
대화 중 확정된 결정. 근거가 약한 항목은 "미확인/추정"으로 표기한다.

- **(1) 하이레벨 요약** *(3–6 bullets)* — 이번 세션에서 **구현/결정된 것**의 결과 중심 요약.
  각 항목에 근거(커밋 해시/파일/테스트 수). "무엇을 했다"가 아니라 "무엇이 바뀌었다".
- **(2) 남은 업데이트** *(bullets)* — 아직 안 끝났거나 이월되는 것. 각 항목에 **왜 남았는지 /
  무엇이 필요한지**(예: "John이 값 제공 필요", "공식 미확정")를 한 줄로.
- **(3) Action item 체크리스트** — Notion to-do 블록(`- [ ]`)으로, 착수 순서대로. 각 체크박스는
  **행동 가능한 단위 하나**. 파일/규칙 ID/필요한 입력을 구체적으로.

머리에 한 줄: `generated by /defer-task — from session on {today} (Toronto) · branch {git branch}`.

## 3. 태스크 생성 대상 확정 (아직 쓰지 않는다)

1. **제목**: 이월 작업을 한 줄로 요약 (예: `CoilForge Terra V — R-078 height-fit + follow-ups`).
   Work 행과 Daily 행 **같은 제목**을 쓴다.
2. **중복 방지**: Work Tasks에 같은 제목+Due Date, 또는 Daily Tasks에 같은 제목+Date 행이 이미
   있으면 만들지 말고 John에게 묻는다. (Daily의 그날 "Work" 실행 행은 건드리지 않는다 — 별도 행.)

## 4. Draft → Confirm → Write (절대 먼저 쓰지 않는다)

1. **터미널에 먼저 출력**: 확정된 날짜 `D`, 태스크 제목, 만들 두 행(Work/Daily), 3섹션 본문 전체.
2. **John의 확인을 받는다. 확인 전에는 Notion에 아무것도 쓰지 않는다.**
3. 확인되면 (상호참조 URL을 위해 순서대로):
   a. **Daily Tasks 행 생성** — `notion-create-pages`, parent = `collection://08ef144c…`:
      `Name`=제목, `date:Date:start=D`, `date:Date:is_datetime=0`, `Status="Not started"`,
      `Impact`/`Priority`=`High`. 본문 = 3섹션 markdown. → 생성된 **Daily URL** 확보.
   b. **Work Tasks 행 생성** — `notion-create-pages`, parent = `collection://d35b1602…`:
      `Name`=제목, `date:Due Date:start=D`, `date:Due Date:is_datetime=0`, `Status="Not Started"`,
      `Impact`/`Priority`=`High`. 본문 = 3섹션 markdown + 맨 위에 `🔗 Daily 행: {Daily URL}`.
      → 생성된 **Work URL** 확보.
   c. **Daily 행 본문에 Work URL 상호참조 추가** — `notion-update-page` `insert_content`
      (position start) 로 `🔗 Work 캘린더 행: {Work URL}` 한 줄 넣는다. (관계가 없으므로 이
      URL 상호참조가 유일한 연결이다 — 양쪽 다 넣어야 어느 캘린더에서든 상대를 찾는다.)

## 5. 결과 요약 (3~5줄)

- 이월 날짜 `D` (Toronto)
- Work Tasks 행 제목 + URL · Daily Tasks 행 URL (상호참조 확인)
- 체크리스트 항목 수
- 검색으로 못 잡았을 수 있는 세션 항목이 있으면 정직하게 한 줄
